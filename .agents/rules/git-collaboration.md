# Git Collaboration Rules

This is a shared repository with multiple teammates. Follow these rules strictly:

## 1. Always Pull First
Before writing any new code or making changes, run `git pull` to fetch the latest updates from teammates. Never start working on stale code.

## 2. Component Isolation
Respect the modular component architecture. Only modify components that are assigned to you. Do not touch files that teammates are actively working on. When uncertain about ownership, ask the user before editing.

## 3. Communicate Before Pushing
Never run `git push` without first informing the user what files are being pushed and getting explicit confirmation. Summarize the changes and wait for approval before pushing.
